# 시연 시나리오 — 11분

**준비물** 노트북, `시작하기.ps1` 실행해 둘 것, `backend/.env` 에 `OPENAI_API_KEY` 입력 완료, 브라우저 탭 2개(화면 / Swagger)

> ⏱ 시작 전에 **`시작하기.ps1` 을 미리 돌려두세요.** 무료 서버 콜드스타트나 패키지 설치가 시연 중에 걸리면 흐름이 끊깁니다.

---

## 0분 ~ 1분 · 한 문장으로 무엇인지

> "제철 식재료는 값이 크게 움직입니다. 그런데 ChatGPT에게 '이번 달 장바구니 값 어때?'라고 물어도 제 기록을 모르니 일반론만 나옵니다.
> 이 서비스는 **제가 기록한 2년치 품목별 가격 시계열을 GPT의 시스템 프롬프트에 주입해서**, 내 데이터를 아는 비서를 만든 겁니다."

화면을 띄우면 **맨 위가 채팅창**입니다. 그걸 가리키며:

> "이 앱의 입구는 표가 아니라 대화입니다. 사용자는 '배추 2,017원'을 사러 오는 게 아니라 **김치찌개를 하러** 오거든요."

## 1분 ~ 3분 · 대화가 화면을 움직인다 (핵심 시연)

빠른 질문 버튼 중 **「김치찌개 재료값」** 을 누릅니다.

답이 나오면서 아래에 **🛒 필요한 재료** 카드가 나타납니다.

> "제가 '김치찌개'라고만 했는데 배추·대파·양파가 올라왔습니다. 여기 이유도 적혀 있고요 — `김치찌개 → 배추, 대파, 양파`.
> 그리고 2가지 합계 6,024원, '대파는 미루거나 대체를 고려하세요'까지 붙습니다."

여기서 설계 이야기를 한 줄:

> "**재료를 뽑는 건 GPT가 아니라 서버입니다.** GPT에게 시키면 같은 문장인데 매번 다르게 답하고 토큰도 씁니다. 서버에서 사전 대조로 뽑으면 결정적이고, 공짜고, 틀려도 화면 정렬만 바뀝니다.
> 그리고 그 음식 표는 **추천 기능과 같은 파일을 씁니다.** 두 벌로 들고 있으면 한쪽만 고쳐져서 '추천은 되는데 대화에서는 못 알아듣는' 일이 반드시 생깁니다."

## 3분 ~ 4분 · 축이 두 개 (오른쪽 판정 카드)

오른쪽 **🚦 오늘의 판정** 을 짚으며:

> "이 프로젝트에서 제일 공들인 부분입니다.
> **평년 대비**와 **전주 대비**, 두 축을 같이 봅니다. 방향이 서로 반대일 때가 많은데 —
> 예년 이맘때보단 비싼데 지금은 내려오는 중, 이런 상황이요."

> "**축이 하나면 이 구분이 안 됩니다.** 평년보다 싼데 오르는 중이면 '지금 사라'고, 평년보다 싼데 내리는 중이면 '기다려도 된다'가 됩니다. 정반대 결론이에요."

맨 아래 📐 줄을 가리키며:

> "평년을 어떻게 구했는지도 화면에 그대로 적어뒀습니다. **같은 달력 시기 ±7일의 다른 해 기록**을 평균 냈습니다. 같은 해 값은 뺐고요 — 자기 자신과 비교하면 항상 0%가 나오니까요."

## 4분 ~ 5분 · 조건으로 고르기 (보너스②)

**🎛️ 조건으로 고르기** 로 내려가서 `국·찌개` + `밥반찬` 을 누르고 **추천받기**.

> "조리법·목적·계절감·난이도·편의성을 넣으면 음식 82종 중에서 골라서, **그 재료를 지금 값으로 판정해** 같이 보여줍니다. 비싼 재료엔 대체재가 붙고요."

여기서 실패담을 하나 곁들이면 좋습니다.

> "처음엔 모든 조건을 가중합으로 더했는데, '국물 요리'를 골랐더니 **호박전**이 1위로 올라왔습니다. 계절감·가격 점수가 높아서요.
> 조리법은 취향이 아니라 사용자가 **직접 고른 조건**이라, 곱셈 관문으로 바꿨습니다. 안 맞으면 0.25배."

**「AI에게 묻기」** 로 토글해 보이며:

> "같은 손잡이로 두 가지를 할 수 있게 했습니다. 서버 추천은 같은 조건이면 항상 같은 결과가 나오고, AI 모드는 말투가 자연스럽습니다. **다만 AI 모드에서도 값과 판정은 서버 것을 씁니다.** GPT는 조건에 맞는 음식을 고르는 말투만 담당합니다."

## 5분 ~ 6분 · 분류로 찾기

**🥬 품목별 시세** 위의 분류 막대에서 `채소` → `근채류` 를 누릅니다. 목록이 좁혀집니다.

> "대·중·소 3단입니다. 두 가지를 지켰는데 —
> 하나, **데이터에 있는 품목만** 나무를 만듭니다. 카탈로그 전부를 보여주면 가격 없는 가지를 눌렀을 때 빈 화면이 나오고, 사용자는 그걸 고장으로 봅니다.
> 둘, **대분류를 고르기 전엔 아랫줄을 안 만듭니다.** 3단을 처음부터 다 펼치면 버튼이 60개가 넘어서 오히려 못 찾습니다."

품목 줄 하나를 눌러 펼치며:

> "누르면 근거가 나오고, 여기서 바로 그래프나 대체 재료로 이어집니다."

## 6분 ~ 7분 · Function Calling (스크린샷 1·5번 장면)

채팅창으로 돌아가서:

```
6월 중에 제일 쌌던 날이 언제야?
```

답변 아래 **🔧 도구 호출 추적**을 가리키며:

> "요약에는 '전체 최저가'만 있고 '6월 한정 최저가'는 없습니다. 그래서 GPT가 스스로 판단해서 `find_extreme` 도구를 호출했습니다. 인자까지 다 찍혀 있습니다."

이어서:

```
배추가 비싼데 뭘 대신 쓸까?
```

> "이건 조회가 아니라 **판단이 필요한 도구**입니다. 도구가 전부 조회면 GPT는 그냥 첫 번째 것만 부릅니다. 성격이 다른 게 섞여야 '고르는' 행동이 실제로 나타납니다. 지금 도구가 11종인데 그중 셋이 판단형입니다."

> "대체재 표에는 **가격을 절대 안 적었습니다.** 값은 항상 데이터에서 계산합니다. 표에 적어두면 데이터가 바뀌어도 표는 안 바뀌어서 거짓말을 하게 되거든요."

## 7분 ~ 8분 · 데이터 시각화 4종 (보너스②)

**📊 데이터 시각화** 에서 탭을 차례로 넘깁니다.

**평가 지표** 탭:

> "여섯 축입니다. 그런데 **성격이 두 가지**예요. 계절성·가격·신선도는 실제 가격에서 계산한 **측정값**이고, 기호도·편의성·쉬움은 제가 적어 둔 **참고값**입니다.
> 그래서 초록 실점과 흰 점으로 나눠 그렸습니다. 하나로 합친 종합점수만 보여주면 틀렸을 때 어디가 틀렸는지 알 수 없어서요."

**SWOT** 탭:

> "네 칸 전부 서버가 계산합니다. GPT한테 시키면 그럴듯한 문장이 나오지만 근거가 매번 달라집니다. 강점·위협은 원래 계산으로 나오는 거예요 — 평년보다 싸면 강점, 다음 달 평균이 더 비싸면 위협.
> 그래서 줄마다 근거가 붙습니다: `배추 다음 달 평균이 13% 더 쌉니다 — 미룰수록 유리`."

**분류별 히트맵** 탭:

> "분류 × 12개월입니다. 칸의 값은 절대 가격이 아니라 **연평균 대비 그 달 평균**이에요.
> 처음엔 절대값으로 칠했는데, 대하가 3만원이라 표 전체를 덮어서 채소가 한 칸도 안 보였습니다."

**가격 분포** 탭:

> "막대가 그 품목의 1년 범위고 점이 지금 값입니다. '지금이 이 품목 기준으로 어디쯤인가'에 답합니다."

## 8분 ~ 9분 · 향후 추이선 — 없는 데이터를 다루는 법

그래프 카드에서 **🔮 향후 추이선** 을 펼칩니다.

> "여기가 제일 조심한 부분입니다."

점선과 띠를 가리키며:

> "같은 달력 시기의 **다른 해 평균**을 뼈대로, 최근 14일 수준과 30일 추세를 절반만 반영해 계산합니다. 추세를 그대로 늘렸더니 60일 뒤 값이 터무니없어져서 감쇠를 넣었습니다."

**작황 악화** 손잡이를 +10%로 밀어 선이 올라가는 걸 보여주며:

> "요청은 '환율·날씨·운송비를 반영해 달라'였는데, **저희 DB엔 그 데이터가 없습니다.**
> 없는 걸 있는 척할 수는 없어서 **가정값 손잡이**로 뒀습니다. '환율이 5% 오르면?'을 밀면, 품목별 민감도를 곱해서 선이 움직입니다. 수산물은 환율에 0.30, 산나물은 날씨에 0.95로요.
> 이건 예언이 아니라 **조건을 넣었을 때의 계산**이고, 화면에도 그렇게 적어뒀습니다."

띠를 짚으며 마무리:

> "선 하나만 그리면 사용자가 그걸 정답으로 읽습니다. 그래서 평년의 흩어짐으로 만든 띠를 같이 그렸어요. **띠가 넓다는 건 그만큼 못 믿을 품목이라는 뜻이고, 그 사실이 값 자체만큼 중요합니다.**"

**🌙 어둡게** 를 눌러 다크 모드도 함께 보여주면 좋습니다.

> "색을 CSS 변수로만 줬더니 SVG 그래프까지 저절로 따라옵니다. canvas였으면 다시 그려야 했어요."

## 9분 ~ 10분 · 겪은 문제 하나 (가장 강한 마무리)

**시간이 없으면 이것만이라도 말하세요.**

> "개발 중에 데이터가 갑자기 1,460건, 두 배가 됐습니다.
> 원인은 제가 편하려고 넣은 기능이었어요 — '서버 켜면 데이터 자동으로 넣기'. 그게 **테스트에서도 돌아서** 테스트가 넣은 데이터와 겹친 겁니다.
> 켤 수 있게만 만들고 **끌 수 있게는 안 만든** 게 문제였습니다. 지금은 3단계로 나눴고, 테스트 **첫 줄**에 '시작할 때 0건인지' 검사를 넣어서 다시 생기면 바로 걸리게 했습니다."

여유가 있으면 하나 더:

> "테스트가 빨간 줄 2개를 낸 적이 있는데, **하나는 테스트가 틀린 거였고 하나는 진짜 구멍**이었습니다. '시원하다'의 '원'을 가격으로 오인한 게 하나, 바지락이 대체재 표에서 빠진 게 하나. 빨간 줄을 그냥 넘겼으면 진짜 구멍을 놓쳤을 겁니다."

> "품목을 12개에서 27개로 늘렸을 때도 똑같은 일이 있었습니다. 테스트가 두 개를 잡았는데, 하나는 새 품목 5개가 대체재 표에 없다는 **진짜 구멍**이었고, 하나는 제가 도구 개수를 `== 6` 으로 못 박아 둬서 깨진 거였습니다.
> 두 번째를 고칠 때 개수를 7로 바꾸지 않고, **스키마와 구현의 키가 일치하는지**를 검사하도록 바꿨습니다. 기능을 늘릴 때마다 깨지는 테스트는 결국 주석 처리되거든요."

## 예상 질문 대응

| 질문 | 답 |
|---|---|
| **RAG를 왜 안 썼나?** | 하루 한 줄의 정형 시계열이라 의미 검색이 필요 없습니다. 요약 주입으로 충분하고 토큰도 훨씬 적게 듭니다. |
| **파인튜닝은?** | 바뀌는 건 답변 형식이 아니라 **데이터**입니다. 파인튜닝은 매일 바뀌는 데이터를 못 따라갑니다. |
| **데이터가 10배가 되면?** | 프롬프트 길이는 거의 그대로입니다. 요약 문장만 들어가니까요. 다만 Firestore 정렬을 앱에서 하고 있어서, 수십만 건이면 색인을 만들어 DB 정렬로 바꿔야 합니다. |
| **평년을 왜 ±7일로 잡았나?** | 하루만 비교하면 그날 우연한 급등에 휘둘립니다. 너무 넓히면 계절이 섞입니다. 실제로 ±7일 창이 월 경계 절벽에 걸려 평년값이 오염된 적이 있어서, 데이터 쪽 계절 계수를 보간으로 고쳤습니다. |
| **판정 기준(−12%, −4%…)은 어디서 나왔나?** | 제가 정한 값입니다. 근거는 실용성 — 평년 대비 4% 차이는 장에서 체감이 안 되고, 12%는 확실히 체감됩니다. 값은 `VERDICT_BANDS` 한 곳에만 있어서 바꾸면 프롬프트·화면·문서가 함께 따라옵니다. |
| **GPT가 판정을 무시하면?** | 프롬프트에 "판정을 뒤집지 마세요"를 명시했고, 그 규칙이 실제로 실리는지 테스트합니다. 다만 100% 보장은 아니라서, 판정 자체는 화면에 **서버 값 그대로** 별도 표시합니다. |
| **데이터가 진짜가 아니지 않나?** | 맞습니다, 생성 데이터입니다. KAMIS 오픈API 인증키가 발급 전이라서요. 다만 **변환 스크립트를 미리 만들어 뒀고** 가짜 CSV로 결측 보간까지 검증했습니다. 키가 나오면 한 줄로 교체됩니다. |
| **왜 프레임워크를 안 썼나?** | 과제 제약입니다. 그런데 해보니 SVG를 직접 다루는 게 다크 모드에는 오히려 유리했습니다. |
| **가격 예측이 얼마나 정확한가?** | 정확도를 주장하지 않습니다. 이건 **과거 계절 패턴에서 뽑은 계산**이고, 작황 급변·명절 수요처럼 패턴에 없던 사건은 못 맞힙니다. 그래서 선 하나가 아니라 **불확실성 띠**를 함께 그리고, 화면과 API 응답 양쪽에 계산 방법과 한계를 적어 둡니다. |
| **왜 환율·날씨 API를 안 붙였나?** | 정확도는 오르지만 외부 키가 2개 늘고, Render에서 그 호출이 실패하면 화면이 멈춥니다. 그리고 **관측치가 아닌 걸 관측치처럼 보여주는 게 더 나쁩니다.** 가정값 손잡이로 두어 사용자가 시나리오를 직접 넣게 했습니다. |
| **ARIMA 같은 걸 쓰지 그랬나?** | 2년치 일별 데이터로 학습하면 잡히는 건 계절 성분입니다. 그건 지금의 '같은 시기 다른 해 평균'이 이미 하고 있는 일이라, 라이브러리와 학습 시간만 늘고 설명은 어려워집니다. **설명할 수 있는 계산**을 택했습니다. |
| **기호도·난이도 점수는 근거가 뭔가?** | 근거가 있는 수치가 아닙니다. 평생학습센터 조리 수업에서 다뤄 본 감각을 옮긴 **참고값**입니다. 그래서 측정값과 섞지 않고, API 응답에 `source` 를 실어 보내 화면에서도 나눠 그립니다. |
| **품목이 27개뿐인 이유는?** | Firestore 무료 요금제가 하루 쓰기 2만 건이 한도입니다. 27품목 × 730일 = 19,710건이 딱 들어갑니다. 일수를 줄일 수는 없어요 — **평년 대비는 다른 해의 같은 시기와 비교**하는 거라 2년치가 있어야 성립합니다. 카탈로그는 94품목까지 준비돼 있고 `--profile` 로 바꿉니다. |

## 만약 시연 중 문제가 생기면

| 증상 | 대처 |
|---|---|
| 화면은 뜨는데 데이터가 없음 | 백엔드 창이 켜져 있는지 확인. 오른쪽 위 뱃지가 빨강이면 서버가 꺼진 것 |
| AI 답변이 503 | `.env` 의 `OPENAI_API_KEY` 미입력. **당황하지 말고** "키 없이도 요약·판정·데이터 관리는 다 됩니다"라고 말하고 넘어가기 |
| 배포 화면에서 아무것도 안 나옴 | Render `ALLOWED_ORIGINS` 에 Vercel 주소 누락(CORS). 로컬 화면으로 전환해 시연 |
| 첫 요청이 한참 걸림 | Render 콜드스타트. 안내 배너가 뜨는 걸 **오히려 시연 소재로** 쓰기 |
