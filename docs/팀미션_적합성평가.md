# 팀미션 적합성 평가

## 1. 평가 대상

- 업로드된 `팀미션.pdf`
- 기존 `jecheol-planner` 코드와 문서
- 새로 설계한 제철밥상 플래너 2.0 화면 구조

## 2. 종합 판정

**조건부 적합**이다. 현재 프로젝트는 팀미션의 AI Agent·RAG·기억·Frontend/Backend·README·GitHub·시연 요구를 충족할 수 있는 기반을 갖췄다. 다만 사진·바코드 기능, 장기기억의 사용자 단위 관리, 실제 배포 증빙, 데이터 신뢰성 검증을 보완해야 최종 제출 수준이 된다.

## 3. 요구사항별 판정

| 팀미션 기준 | 현재 상태 | 판정 | 보완 사항 |
|---|---|---|---|
| AI Agent | 계획·추천·코칭 구조와 AI 채팅 존재 | 적합 | 사진·바코드 결과를 Agent 도구와 연결 |
| RAG | 도메인 데이터와 요약을 프롬프트에 주입 | 조건부 적합 | 지식 문서·출처·검색 결과를 명시적으로 관리 |
| Long-term Memory | 대화 저장 API 존재 | 조건부 적합 | 사용자별 식단·장바구니·선호 저장 필요 |
| Planning Agent | 조건 기반 음식·장바구니 추천 존재 | 적합 | 일반 가정용 입력 흐름 단순화 |
| Coaching Agent | AI 대화 기능 존재 | 적합 | 가격 근거와 조언을 분리 표시 |
| Frontend | HTML·CSS·JavaScript 화면 존재 | 적합 | 현재 화면을 단순한 메뉴 구조로 재배치 |
| Backend | FastAPI 라우터·서비스 구조 존재 | 적합 | 이미지·바코드 엔드포인트 추가 |
| 요구사항 문서 | README·결과보고서·시연자료 초안 존재 | 조건부 적합 | 실제 URL·실행 화면·역할 분담 확정 |
| GitHub | Git 구조 존재 | 조건부 적합 | 비밀 파일 제거 후 원격 저장소 확인 |
| 비기능 요구 | 오류 메시지·기본 검증 존재 | 조건부 적합 | 인식 오류·API 지연·데이터 부족 상태 추가 |

## 4. 팀 역할 제안

| 역할 | 담당 |
|---|---|
| PM/Backend | 요구사항, FastAPI, 가격·장바구니 API |
| Frontend | 반응형 화면, 사진·바코드 UI, 접근성 |
| AI/Data | 추천 규칙, RAG, 가격 분석, 검증·리포트 |

## 5. 최종 제출 전 필수 조치

1. 가격 CSV가 실제 2년치인지 검증한다.
2. 같은 날짜의 여러 가격을 중앙값으로 집계한다.
3. `backend/.env`와 `serviceAccountKey.json`을 저장소에서 제거한다.
4. 인증키가 노출된 증빙 이미지를 교체한다.
5. 사진·바코드 인식 결과 확인 화면을 구현한다.
6. 실제 Frontend URL·Backend URL·Swagger URL을 README에 입력한다.
7. 팀원별 역할과 시연 순서를 확정한다.
