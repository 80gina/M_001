# AI 네이티브 Final Project 제출보고서

## 1. 프로젝트 개요

- 프로젝트명: 제철밥상 플래너 · AI 비서
- 문제: 제철 식재료가 실제로 저렴한지 판단하기 어렵고, 가격 확인·식단 결정·시장 기록·장바구니 계산이 여러 서비스로 나뉘어 있다.
- 1차 사용자: 일반 가정 사용자
- 2차 사용자: 요리교실 강사
- 해결: 가격 시계열과 제철 지식을 근거로 구매 시점을 설명하고, 추천부터 시장 기록과 비용 계산까지 한 흐름으로 연결한다.

## 2. 사용자 요구와 해결 방식

| 사용자 요구 | 해결 기능 | 구현 위치 |
|---|---|---|
| 오늘 무엇을 먹을지 빠르게 결정 | 인원·시간·분위기 기반 밥상 추천 | `frontend/simple.html`, `simple.js` |

## 3. AI 기술 적용

### 3.1 AI Agent

`chat_service.py`는 사용자의 질문, 최근 대화, 데이터 요약을 GPT에 전달합니다. 모델은 `tools.py`에 정의된 11개 Function Calling 도구 중 필요한 도구를 선택하고 최대 3라운드까지 실행한 뒤 최종 답변을 생성합니다.

### 3.2 검색 증강(RAG 방식)

벡터 DB를 사용하는 문서 RAG가 아니라 **구조화 데이터 검색 증강**을 적용했습니다. Agent가 가격 기록·통계·품목 분류·제철 정보·대체재·이전 대화를 조회하고, 조회 결과를 답변 컨텍스트에 추가합니다. 따라서 일반론이 아니라 저장소 데이터에 근거해 답합니다.

### 3.3 Long-term Memory

`conversations` 컬렉션에 제목·메시지·생성 시각을 저장합니다. 목록에서는 미리보기만 불러오고, 선택한 대화에서는 전체 메시지를 다시 불러와 같은 대화 ID로 이어서 질문합니다.

### 3.4 자동화 워크플로우

요청 한 번으로 다음 과정이 자동 실행됩니다.

`질문 수신 → 가격 요약 → 서버 판정 → Agent 도구 선택 → 근거 조회 → 답변 생성 → 대화 저장`

## 8. AI 윤리와 안전

1. 생성형 AI가 사용된 추천·설명임을 화면에 표시한다.
2. AI가 구매를 자동 확정하지 않고 사용자가 최종 판단한다.
3. 사진 인식 후보를 자동 저장하지 않고 사용자가 선택·수정한다.
4. API 키와 서비스 계정 정보는 환경변수로 관리한다.
5. 가격 데이터가 부족하면 확정적 표현 대신 데이터 부족 상태를 표시한다.
